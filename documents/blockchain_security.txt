Blockchain security relies on a few core mechanisms working together. First, cryptographic hashing: each block of transactions contains a hash of the previous block, so if anyone tampers with an old block, every subsequent block's hash breaks, making tampering immediately detectable. Second, consensus mechanisms (like Proof of Work or Proof of Stake) require the majority of participants in the network to agree before a new block is accepted, which prevents any single actor from rewriting history unless they control a majority of the network's resources.

Common attack vectors on blockchain systems include the 51% attack (an actor gaining majority control of the network's mining/validation power to rewrite transaction history), smart contract vulnerabilities (bugs in the code that runs on top of the blockchain, which have led to major fund thefts in the past), and private key theft (since blockchain identity is tied entirely to cryptographic keys, losing or leaking a private key means losing control of the associated assets with no central authority to reverse it).

Because blockchains are decentralized and immutable, security here is less about "patching a server" and more about getting the initial design right — smart contract code is typically audited extensively before deployment specifically because bugs can't be quietly patched after the fact the way a normal web application can be.
